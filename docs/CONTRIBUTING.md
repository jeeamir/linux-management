# Contributing

## Workflow

1. Create an issue or agree on a focused change.
2. Branch from the latest `main`.
3. Make small commits with clear messages.
4. Update documentation and tests with the code.
5. Open a Pull Request and complete every section of the template.
6. A reviewer checks functionality, organization, documentation,
   maintainability, potential problems, and security.
7. Address comments with a new commit so the review history is visible.
8. Merge only after approval and passing tests.

## Commit style

Use an imperative subject of no more than about 72 characters, for example:

```text
Add disk threshold validation
Document recovery workflow
Fix archive permission handling
```

## Review checklist

- Does the change work and fail safely?
- Is the repository organization clear?
- Are behavior and limitations documented?
- Are variables quoted and inputs validated?
- Can another maintainer understand and extend it?
